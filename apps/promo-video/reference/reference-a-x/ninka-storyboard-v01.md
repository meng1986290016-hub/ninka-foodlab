# Ninka FoodLab 原创 Launch Video Storyboard v0.1

## 当前提案

这是一版待确认的原创建议，不是最终脚本，也尚未进入 Remotion 实现。

- 主画幅：16:9 原生横版，建议 2560×1440。
- 帧率：30 fps。
- 建议时长：约 42 秒。
- 核心承诺：把分散的原料、配方、复核和研发输出放进同一个本地工作台。
- 核心差异：数据默认留在本地；AI 只能提案；正式数据由人确认。
- 表现方式：Ninka 品牌排版与真实 UI 交替，不做连续屏幕录制，也不复刻 Clipwing 的品牌场景。

## 已确认镜头细化

### 第一镜：表格管理问题

**建议上屏文字**

> 还在用表格  
> 管理配方和原料吗？

这里将“还在使用表格来……”压缩为“还在用表格……”，含义不变，但更口语，也更适合在 2.8 秒内完成两行阅读。

**时间节奏**

- 00:00.0–00:00.4：米白画面中出现少量表格线、单元格和光标。
- 00:00.4–00:01.2：第一行“还在用表格”进入，“表格”以森林绿强调。
- 00:01.2–00:02.2：第二行“管理配方和原料吗？”进入；背景出现原料、供应商、配方版本、克重等通用字段。
- 00:02.2–00:02.8：多个表格页签与版本轻微层叠，随后向画面中心收拢，为第二镜产品揭示留出转场锚点。

**视觉边界**

- 不出现 Microsoft Excel Logo、专属图标或对其界面的直接复刻。
- 表格只作为“资料分散、版本增多”的视觉隐喻，文字仍是第一视觉重点。
- 不把画面做成杂乱报错场景，保持 Ninka 应有的克制、专业和高级感。

### 第二镜：产品揭示

保持现稿，不修改：Ninka 符号聚合成 Logo，并出现 **“食品研发的本地工作台”**。

### 第三镜：直接展示原料库

**镜头重点**

让观众在约五秒内（含进入配方工作台的转场）看懂原料库的三层信息结构，而不是讲一条抽象价值主张：

1. 左侧是按通用名称整理的原料，例如饮用水、脱脂乳粉、可可粉、赤藓糖醇和白砂糖。
2. 右侧是当前原料对应的具体供应商版本，显示供应商、型号/规格、当前含税价、数据完整度和更新时间。
3. 打开编辑侧栏后，可以看到营养数据；基本信息中还可维护密度与研发记录。

**时间节奏**

- 00:05.6–00:06.3：第二镜的 Ninka Logo 缩回应用左上角，原料库界面完整展开。
- 00:06.3–00:07.2：光标经过左侧原料列表并选中“可可粉”；提示 **“按通用原料归类”**。
- 00:07.2–00:08.4：视线聚焦右侧“演示供应商 B / 低脂可可粉 CP-10 / ¥48.00/kg”；提示 **“供应商、型号与价格”**。
- 00:08.4–00:09.6：点击编辑并打开“营养成分”侧栏；提示 **“营养数据与完整度”**。
- 00:09.6–00:10.1：侧栏收回并保持选中的“可可粉”行，为转场建立清楚的视觉锚点。

**制作建议**

- 不增加占据半屏的大标题，让真实产品界面成为这一镜的第一视觉重点。
- 提示采用贴近对应区域的小标签或细线标注，一次只出现一条，最多三条。
- 不快速滚动整个原料列表；用一个具体原料完成“分类 → 供应商版本 → 营养详情”的完整路径。
- 继续保留“演示数据”标识，避免示例内容被误认为真实供应商资料。
- 原料库主体为 4.5 秒，后接 0.7 秒转场；这一段合计 5.2 秒，后续镜头已统一顺延。

### 第三镜到第四镜：选中原料 Match Move

**转场逻辑**

不是把整个原料库窗口直接淡出，而是让观众一直跟着同一个对象——“可可粉”：

1. 原料库其他区域轻微后退、降低亮度并虚化。
2. “可可粉 / 低脂可可粉 CP-10”所在行从表格中浮起，原料名称保持清晰。
3. 供应商、价格等字段淡出，同时克重、单位等配方字段在相近位置出现。
4. 配方工作台界面从这行原料周围展开，转场完成后才开始介绍实时复算。

**制作边界**

- 这是视觉上的 match move，不表现“点击原料库即可直接加入配方”，避免制造不存在的产品功能。
- 光标在转场开始前停止，不增加虚构按钮或点击动作。
- 声音使用一次轻选择音、短促空气移动声和落位音，不使用夸张 glitch 或重低音冲击。

### 第四镜：配方实时复算

保持现稿，不修改：在配方工作台修改一项克重，让投料、出成、得率、营养、成本依次更新，并出现 **“改一处，整份配方一起复算。”**

### 第四镜到第五镜：打开 Ninka Agent

**转场逻辑**

1. 配方联动数值完成更新并稳定下来。
2. 相机从局部汇总区拉回完整配方工作台。
3. 光标移动到界面中真实存在的 **“Ninka Agent”** 入口并点击。
4. Agent 面板从入口位置向画面主体展开，工作台退到背景或作为当前配方上下文保留。

这个转场使用真实产品入口，可以表现为一次真实点击；与上一处“原料行进入配方”的电影化 match move 不同。

### 第五镜：Agent 能力介绍

**用户输入**

> 你能帮我干些什么？

**Agent 回答脚本**

> 我可以帮你：  
> 整理原料资料，生成待复核草稿  
> 结合原料库生成配方提案  
> 根据配料表与营养标签进行逆向估算  
> 复盘当前配方，整理下一轮打样建议  
> 正式写入前，需要你确认

**时间节奏**

- 00:17.2–00:18.0：Agent 界面展开并完整停留，观众先认出这是一个对话工作区。
- 00:18.0–00:19.4：输入并发送 **“你能帮我干些什么？”**。
- 00:19.4–00:19.8：显示短暂思考状态，不长时间等待。
- 00:19.8–00:23.4：回答快速流入；四项能力依次形成清晰卡片，每项约停留 0.7–0.9 秒。
- 00:23.4–00:24.2：四项能力同时留在画面中，底部出现 **“正式写入前，需要你确认”**；“生成配方提案”卡片轻微强调，为下一镜预留衔接。

**能力卡的辅助说明**

- **整理原料资料**：从标签、规格书或表格建立待复核原料草稿。
- **生成配方提案**：结合原料库，进行营养、成本、投料和数据完整度试算。
- **逆向产品标签**：给出可编辑估算，并标明关键假设和无法判断项。
- **复盘研发记录**：基于已记录事实，整理需要确认的内容和下一轮打样建议。

**制作边界**

- 回答内容采用可重复的合成演示状态，不在渲染视频时临时调用外部模型。
- 不使用“自动优化配方”“一键完成合规”“自动写入正式数据”等超出现有能力的文案。
- “啪啦啪啦”的速度感由流式文字、细小状态音和卡片依次落位实现；最终仍需给观众足够阅读时间。

### 第六镜：根据原料库生成配方提案

第六镜不再展示人工确认闭环，也不切换到新的功能页面。它直接顺着第五镜的同一段 Agent 对话继续。

**用户输入**

> 请根据原料库里的现有原料，帮我生成一份低糖方向的可可饮品配方提案。

使用“低糖方向”而不是直接宣称“低糖产品”，因为这一步只是研发提案，是否满足营养声称仍需按适用标准和产品类别复核。

**Agent 处理状态**

1. 正在读取原料库中的具体供应商版本
2. 正在试算投料、营养、成本与数据完整度
3. 正在生成配方提案

**Agent 简短回答**

> 已结合原料库中的具体供应商版本，完成投料、营养和成本试算，并生成一份可编辑配方提案。

**配方提案卡**

| 原料 | 演示用量 |
| --- | ---: |
| 饮用水 | 894 g |
| 脱脂乳粉 | 50 g |
| 可可粉 | 28 g |
| 赤藓糖醇 | 25 g |
| 白砂糖 | 2 g |
| 复配稳定剂 | 1 g |
| **合计** | **1000 g** |

卡片保留 **“演示数据”** 与 **“待复核”** 标记，并用一行小字提示：**“‘低糖’仅为研发方向，不构成营养声称。”** 不点击“查看完整提案”，也不进入接受、写入或创建正式版本的流程。

**时间节奏**

- 00:24.2–00:25.9：能力卡淡回对话历史，输入并发送新的配方任务。
- 00:25.9–00:27.1：三个处理状态快速依次完成。
- 00:27.1–00:28.0：Agent 简短回答流入。
- 00:28.0–00:30.6：配方提案卡展开，六项原料与用量依次落位。
- 00:30.6–00:31.2：完整提案停留，保证观众看见它确实使用了原料库中的原料。

**制作边界**

- 使用隔离的合成演示数据，不调用真实供应商资料。
- 不在视频渲染时临时调用外部模型；回答与配方内容固定可复现。
- 不强调“自动完成”，也不把待复核提案表现成已经进入正式配方库的数据。

## 镜头语言与参考片的关系

这是“借结构、不借表面”的改写：

- 借鉴文案段与 UI 证明段的交替，但采用 Ninka 米白/森林绿体系。
- 借鉴光标、局部放大、卡片视差和硬切重置，但改成食品研发真实动作。
- 借鉴一镜一个结果，不使用参考片的云层、山丘、紫色 blur、原品牌排版或相同 CTA。
- 参考片有多段发布工作流；Ninka 只保留一个闭环，避免约 42 秒内变成功能清单。

## Remotion 组件草案

下一里程碑确认后，建议新增独立合成，不覆盖现有 45 秒横版：

- `KineticStatement`：逐词排版、裁切和黑白/品牌色重置。
- `ProductStage`：可放截图或重建 UI 的可缩放产品舞台。
- `CursorActor`：可编辑路径、点击和停顿。
- `CameraRig`：push-in、focus、snap zoom 和卡片视差。
- `MetricCascade`：配方数值联动更新。
- `AgentCapabilityStream`：流式回答与四项能力卡依次落位。
- `ProposalReveal`：处理状态、回答文字与配方提案行的连续展开。
- `MatchWipe`：用选中卡片或 Ninka 符号完成匹配转场。
- `LaunchEndCard`：Logo、定位语和 CTA。

## Remotion Studio 可调项

新合成需要从一开始就把下列参数暴露出来，而不是成片后再补：

- 各镜头时长、总时长和转场时长；
- 主标题、副标题、免责声明、CTA；
- UI 截图来源、缩放、X/Y 位置和圆角；
- 标题字号、行距、对齐和强调色；
- 相机缩放、推镜距离、模糊强度；
- 光标路径、点击时间和停顿；
- 音乐文件、音乐音量、音效音量和关键 cue 时间；
- “演示数据”标记显示与位置。

每个镜头仍应注册为可单独预览的 Composition，主时间线使用明确的 Sequence 时长，方便在 Studio 中逐镜头复核。

## 待确认项

1. 最终 CTA：下载正式版、查看 GitHub，还是进入项目主页。
2. 约 42 秒主片是否合适；若坚持与参考片接近，可扩展到 45–56 秒，但需要增加内容而非放慢现有九镜。
3. 是否使用旁白。当前建议无旁白，以排版、音乐和 UI 音效完成叙事。
4. 首发语言为中文，是否另做英文独立版本。
5. 第七镜如何承接这张“待复核配方提案”，同时避免把它表现成已写入的正式数据。

# 食品研发应用设计说明

日期：2026-07-15  
状态：待用户最终审阅  
目标平台：Windows、macOS

## 1. 产品目标

建设一个面向中国食品研发人员的开源、离线优先桌面应用，形成以下核心闭环：

1. 建立和维护原料数据。
2. 在配方工作台设计配方及半成品配方。
3. 实时计算理论营养、成本、目标达成情况和过敏原。
4. 保存不可变的配方版本并进行比较、复制和归档。
5. 输出研发报告、配方表和营养标签预览。
6. 通过可选的大模型 API 与 MCP 接口扩展为食品研发 Copilot。

第一版以个人本地使用为主，不需要账号、服务器或联网。应用面向所有食品品类，核心数据模型不绑定饮料、烘焙、乳制品等具体类别；品类模板以后作为可选扩展提供。

## 2. 范围与边界

### 第一版包含

- 原料库、配方工作台、配方库、营养与成本计算、目标管理、过敏原提醒。
- 多级半成品配方、配方版本快照、历史结果还原和按最新价格重算。
- GB 28050-2011 与 GB 28050-2025 两套营养标签预览规则。
- Excel/CSV 导入导出、PDF 研发报告、SVG/PNG 标签预览、JSON 完整数据包。
- 配方版本中的一个 Markdown 备注框，用于自由记录工艺、打样、得率和感官评价。
- 完全离线的核心功能，以及可选、默认关闭的 AI/MCP 扩展层。

### 第一版不包含

- 库存、采购订单、供应商阶梯价、排产、审批流或完整 PLM/ERP 功能。
- 独立的打样记录、结构化工艺步骤、感官评分、附件或实验统计模块。
- 食品添加剂法定限量自动判断。
- 特定营养素的热加工损失或保留率模型。
- 多人协作、云端同步、用户权限和国外营养标签规则。
- 操作系统代码签名；正式构建仍提供来源、校验值和可复现构建说明。

营养结果定位为研发理论估算和标签预览，不替代成品检测报告或正式合规审查。

## 3. 核心功能设计

### 3.1 原料库

每种原料至少包含：

- 名称、内部编号、分类、标签和备注。
- 营养数据及其计量基准；内置能量、蛋白质、脂肪、饱和脂肪、碳水化合物、糖、膳食纤维、钠等常用项目，同时允许自定义营养或功能成分。
- 当前含税基准单价、价格单位和更新时间。
- 可选密度；只有密度可用时，体积才能可靠换算为质量。
- 过敏原状态，区分“含有”和“可能含有”。
- 数据来源、来源日期和记录备注。

“未知/未检测”必须与“确认为 0”分开存储。计算结果显示数据完整度、缺失营养项目和相关原料，不能把未知值静默当作零。

初始安装仅提供少量带来源说明的演示原料，以及中文 Excel 模板。用户可以手工创建、复制、批量编辑或导入原料。公共原料数据库以后以可选数据包或插件形式提供，不与应用代码默认共用授权。

### 3.2 配方工作台

工作台支持：

- 添加普通原料或已保存的半成品配方版本。
- mg、g、kg 质量单位；mL、L 体积单位必须通过原料密度换算。
- 用量与配方百分比实时联动，当前投料合计由下方配方用量自动汇总。
- 锁定任意原料的用量或百分比；可指定一个原料自动补足到计划投料总量或 100%。
- 输入出成重量，用于计算成品得率、单位成品成本和每 100g 营养浓度。
- 设置营养与成本目标的上限、下限或区间，并实时显示差值与达标状态。
- 草稿自动保存；显式保存后生成不可变的正式版本。

半成品必须引用一个明确的配方版本，而不是浮动引用“最新版”。升级到新版本必须由用户显式选择。系统在保存前检测直接和间接循环引用，并阻止形成循环依赖。

若自动补足会产生负数、体积原料缺少密度或单位无法换算，系统应阻止计算或保存，并指出具体冲突项。

### 3.3 营养计算与标签预览

- 原料营养统一转换为质量基准后汇总。
- 配方总营养由各原料或半成品版本逐层汇总。
- 每 100g 成品营养按出成重量换算；没有填写出成重量时，使用当前投料合计并清楚标注假设。
- 第一版默认营养全部保留，不对维生素等单项营养设置加工保留率。
- 规则引擎封装各标准版本的强制项目、能量换算、NRV、修约、单位和标签格式，避免将法规规则写死在界面或通用计算层。
- 用户可以在 GB 28050-2011 与 GB 28050-2025 之间切换。保存正式版本时同时冻结所用规则版本；新建配方默认选择 GB 28050-2025，并提示其正式实施日期为 2027-03-16。
- 标签预览和导出必须带“研发估算，不能替代检测报告”的明确标识。

### 3.4 成本计算

成本包括：

- 原料理论成本。
- 由成品得率或整体损耗带来的单位成品成本变化。
- 可选包材项目。
- 可自由添加的其他成本项，例如加工费、检测费或能源费。

输出整批、每 kg、每 100g、每份和每包装单位成本，以及成本构成占比。第一版不建立供应商、采购和库存模块。

正式配方版本冻结当时的原料价格和成本结果。原料价格更新后，历史版本保持原值，同时提供“按当前价格重新估算”的临时视图；该操作不覆盖历史快照。

### 3.5 版本、配方库与备注

- 草稿可编辑并自动保存；正式版本不可原地修改。
- 修改正式版本时复制为新草稿，并记录来源版本。
- 配方库支持名称、编号、标签、状态和更新时间搜索筛选。
- 支持版本差异比较，至少展示原料增删、用量、营养、成本、目标和备注变化。
- 支持复制、归档和安全删除；被其他配方引用的版本不可直接删除。
- 每个版本只有一个 Markdown 备注框。备注跟随版本冻结，复制新版本时自动带入，可记录工艺、打样、实际得率、感官评价、问题和下一步计划。

### 3.6 过敏原

- 原料维护“含有”和“可能含有”两类过敏原。
- 配方自动汇总普通原料及所有层级半成品的过敏原。
- 配方工作台、版本详情和报告中醒目显示汇总结果。
- 第一版仅做信息汇总和提醒，不自动生成最终包装警示语。

### 3.7 导入、导出与备份

- Excel/CSV：原料批量导入导出及可编辑配方表。
- PDF：包含配方版本、计算时间、数据完整度、营养估算、成本构成、目标状态、过敏原和备注的研发报告。
- SVG/PNG：可交给包装设计或用于预览的营养标签图形，带研发估算标识。
- JSON：稳定、带版本号的完整交换格式，用于迁移、备份、插件和 AI/MCP 工具。
- 本地自动备份、手动备份与恢复。升级数据库结构前必须先创建备份；迁移失败时保留原数据库并提供恢复入口。

## 4. 食品研发 Copilot

### 4.1 产品定位

Copilot 作为配方工作台内的可选助手。大模型负责理解目标、提出方案、编排工具和解释结果；营养、成本、单位、目标和配方依赖始终由确定性计算引擎完成。

首个 AI 阶段重点支持：

- 将自然语言需求转换为批量、必选/禁用原料、营养目标和成本目标。
- 搜索原料并生成多个候选配方草稿。
- 调用计算引擎验证候选方案并解释取舍。
- 根据目标调整草稿，例如降糖、降钠、降成本或替换缺货原料。
- 诊断高成本原料、未达标目标、缺失数据和版本变化。
- 读取备注并整理工艺记录、总结问题或生成下一轮打样建议。
- 生成研发报告、成本说明和版本对比摘要。

后续可通过 MCP 接入法规和企业知识库，提供带来源的标签合规辅助审查。AI 不能宣称产品已合规，也不能替代人工或检测机构。

### 4.2 工具与权限

Agent 工具至少覆盖：搜索/读取原料、搜索/读取配方版本、创建草稿、调整草稿、锁定与补足、批量缩放、计算营养与成本、检查目标、比较版本、检查缺失数据/过敏原/循环依赖、读取备注、建议更新备注和生成报告。

权限分级：

- 读取和计算可以自动执行。
- 创建候选草稿可以自动执行，但必须标记为 AI 生成。
- 覆盖原料数据、修改备注、保存正式版本、删除数据和导出敏感配方必须先展示变更并由用户确认。
- 第一版 Agent 不直接修改不可变的正式版本。

### 4.3 模型、隐私与可追溯性

- 使用供应商适配层，不绑定单一大模型；支持用户自行配置 API Key，并为未来本地模型保留接口。
- 没有 API Key 时，核心应用仍完全离线可用。
- API Key 存入操作系统安全凭据存储，不写入 SQLite、日志或导出文件。
- 仅向模型发送当前任务所需的数据，调用前显示将发送的数据范围。
- 保存模型名称、时间、工具调用、数据范围、引用来源和用户确认记录；不要求保存不可控的模型内部推理文本。
- 外部法规、网页和文档视为不可信输入，不能让其改变工具权限或绕过用户确认。

## 5. 技术架构

- 桌面端：Tauri 2。
- 前端：React + TypeScript。
- 本地数据库：SQLite，使用显式迁移和外键约束。
- 计算引擎：独立、无界面的 TypeScript 包，包含单位换算、营养、成本、目标、配方依赖和标准规则。
- 桌面桥接：Rust 仅负责文件系统、数据库、安全凭据、导入导出和系统能力，业务规则不散落在桥接层。
- Agent：独立的供应商适配与工具编排层，通过稳定的应用服务接口调用核心功能。
- 构建发布：GitHub Actions 自动测试并生成 Windows 与 macOS 未签名安装包、SHA-256 校验值和构建记录。

模块边界确保将来可以复用计算引擎和数据交换格式构建 Web 版或 MCP 服务，而不重写业务规则。

## 6. 关键数据实体

- Ingredient、NutrientDefinition、IngredientNutrientValue、Allergen、IngredientPrice。
- Recipe、RecipeDraft、RecipeVersion、RecipeItem、RecipeVersionSnapshot、RecipeNote。
- NutritionRuleSet、FormulaTarget、PackagingCost、AdditionalCost。
- ImportJob、ExportJob、BackupManifest。
- AiProviderConfig、AgentSession、AgentToolCall、AgentApproval。

所有业务实体使用稳定 UUID。正式版本通过快照保存计算所需的原料、半成品、价格和规则数据，避免基础数据更新后改变历史结果。

## 7. 错误处理与数据安全

- 导入前预览字段映射、单位和错误行；错误不能导致部分数据静默写入。
- 保存前验证单位、密度、配方总量、目标、循环依赖和引用完整性。
- 数据库写入使用事务；计算失败时不产生正式版本。
- 未知营养值、缺少来源和过期价格以警告呈现，不伪装为精确结果。
- 删除采用引用检查和二次确认；优先归档而非物理删除。
- 应用崩溃后恢复最近草稿；备份和恢复均校验格式版本与完整性。
- AI、导入文件或外部 MCP 返回的内容不能直接执行系统命令或提升权限。

## 8. 验收与测试

### 计算与数据

- 验证质量/体积/密度换算、百分比联动、锁定与自动补足、批量缩放。
- 验证普通原料、多层半成品、循环引用检测和显式版本引用。
- 验证成品得率对单位成本及每 100g 营养的影响。
- 验证未知值与零值、数据完整度和缺失原料提示。
- 对两套 GB 28050 规则使用独立金样测试，覆盖强制项、能量、NRV、修约和导出一致性。
- 验证历史价格快照不变、按最新价格重算不覆盖历史。

### 工作流

- 从 Excel 导入原料，创建含半成品的配方，设置目标，保存版本，再导出全部格式。
- 更新原料营养或价格后，历史版本仍可完全还原。
- 比较两个版本能准确显示原料、营养、成本、目标和备注变化。
- 被引用版本无法误删；备份可在另一台电脑完整恢复。

### Agent

- Agent 只能通过已定义工具读取和计算，不能直接访问数据库文件。
- 候选方案的营养与成本与手工计算结果一致。
- 修改正式数据、保存版本和删除操作必须触发确认。
- 无 API Key、网络失败、模型超时或无效结构化输出时，核心应用继续可用且草稿不损坏。
- 外部文档中的恶意指令不能绕过工具权限。

### 发布

- Windows 与 macOS 均能从源码构建并安装未签名版本。
- 发布页包含源码、安装包、SHA-256 校验值、安装警告、数据备份说明和 Apache-2.0 许可证。

## 9. 推荐交付顺序

1. 基础工程、数据库、单位与营养/成本计算引擎。
2. 原料库、Excel 导入和数据完整度。
3. 配方工作台、半成品、目标、锁定补足和实时计算。
4. 配方版本、配方库、差异比较、过敏原和备注。
5. 双标准标签、报告导出、备份恢复和未签名发布流程。
6. 供应商无关的 AI 层、受控工具、Copilot 界面和 MCP 扩展点。

核心计算与版本快照稳定后再启用 Agent，避免大模型建立在不稳定的数据和工具接口之上。

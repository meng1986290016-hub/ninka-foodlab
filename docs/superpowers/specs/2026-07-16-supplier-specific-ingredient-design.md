# 供应商版本化原料库设计补充

日期：2026-07-16  
状态：功能方向已逐段确认，待用户审阅书面版本  
关联设计：`2026-07-15-food-rnd-app-design.md`  
影响阶段：第二阶段“桌面外壳与本地数据”、第三阶段“原料库与数据交换”

## 1. 目的与优先级

本补充根据第一版浏览器原型的实际试用反馈，调整原料库的数据粒度和录入界面。核心目标是让研发人员能够在同一种通用原料下维护多家供应商的真实规格，并在配方中选择实际使用的供应商版本。

若本补充与原设计中的原料字段、分类、标签、日期或供应商处理方式冲突，以本补充为准。未涉及的产品范围和技术架构继续沿用原设计。

## 2. 已确认的产品决策

### 2.1 通用原料与供应商版本分离

“脱脂乳粉”等名称代表通用原料；供应商 A 的型号 A1 和供应商 B 的型号 B2 是两个独立的供应商版本。每个供应商版本分别维护价格、密度、营养、规格、来源、研发备注和更新时间。

配方项目必须引用明确的供应商版本，不能只引用通用原料。这样计算结果始终对应明确的价格和营养来源，并为以后比较或替换供应商保留稳定边界。

### 2.2 内部编号改为可选

内部编号不再是必填项，也不参与个人使用场景下的默认识别。它位于供应商版本的“更多字段”中，主列表默认不显示；需要对接企业编码或导入外部数据时仍可使用。

### 2.3 分类可自定义

每个通用原料最多选择一个分类。分类选择器允许直接创建自定义分类，也支持重命名和排序。正在被通用原料使用的分类不能直接删除，必须先迁移引用或将分类归档。

### 2.4 第一版取消标签

标签与备注在当前个人研发工作流中存在较高功能重叠，第一版取消标签字段和相关筛选。分类承担结构化归类，供应商版本的研发备注承担自由记录；搜索支持匹配备注内容。以后出现明确的跨分类批量筛选需求时，再单独设计标签迁移。

### 2.5 日期由系统自动维护

手工填写的“价格日期”和“来源日期”从界面和第一版数据模型中移除，统一为供应商版本的只读字段“最新更新日期”。

供应商版本的正式保存只要改变价格、营养、密度、型号、来源、内部编号或研发备注，就自动更新 `updatedAt`。编辑草稿不会修改更新时间；保存失败也不能修改更新时间。通用原料行不显示更新时间，需要排序时可按其供应商版本中最近的 `updatedAt` 计算活动顺序。

## 3. 数据模型

### 3.1 Category

- `id`：稳定 UUID。
- `name`：用户可见名称，同一活动分类中唯一。
- `sortOrder`：用户定义的排序。
- `createdAt`、`updatedAt`。
- `archivedAt`：归档时间；被引用分类不能物理删除。

### 3.2 MaterialGroup（通用原料）

- `id`：稳定 UUID。
- `name`：通用原料名称，必填。
- `categoryId`：可空，关联自定义分类。
- `createdAt`、`updatedAt`、`archivedAt`。

通用原料不保存供应商价格、营养、密度、来源、标签或研发备注，避免数据归属不清。

### 3.3 Supplier

- `id`：稳定 UUID。
- `name`：供应商名称，活动供应商中唯一。
- `notes`：仅记录供应商层面的简短说明，不承载具体原料的研发观察。
- `createdAt`、`updatedAt`、`archivedAt`。

供应商选择器允许在录入供应商版本时即时创建供应商。第一版不加入采购、联系人、付款、库存或供应商准入模块。

### 3.4 IngredientVariant（供应商版本）

- `id`：稳定 UUID。
- `materialGroupId`：必填，关联通用原料。
- `supplierId`：必填，关联供应商。
- `modelOrSpecification`：供应商型号或规格，可空。
- `internalCode`：内部编号，可空，默认隐藏。
- `currentPrice`：含税基准单价，十进制字符串，可空。
- `priceUnit`：`kg`、`g`、`L` 或 `mL`。
- `densityGPerMl`：密度，十进制字符串，可空。
- `nutritionBasis`：`per_100g` 或 `per_100ml`。
- `source`：数据来源说明，例如供应商规格书、包装营养标签或检测报告。
- `researchNotes`：该供应商产品的溶解性、风味、应用表现、限制和待验证事项。
- `createdAt`、`updatedAt`、`archivedAt`。

同一通用原料下出现相同“供应商＋型号/规格”时提示可能重复，但用户明确确认后允许保存。原因是同一型号可能存在不同地区、包装或阶段性的真实记录差异。

### 3.5 NutrientDefinition 与 IngredientNutrientValue

内置营养项目：

- 能量（kJ）
- 蛋白质（g）
- 脂肪（g）
- 饱和脂肪（g）
- 碳水化合物（g）
- 糖（g）
- 膳食纤维（g）
- 钠（mg）

用户可增加自定义营养或功能成分。每个营养值关联一个供应商版本和营养定义，值使用可空十进制字符串：

- `null`：未知、未提供或未检测。
- `"0"`：明确确认是零。
- 其他十进制字符串：来源提供的数值。

供应商提供的原始营养值与系统推算值不得写入同一字段。推算结果以后由计算层单独生成并标明依据。

## 4. 原料库界面与工作流

### 4.1 分组列表

主列表以通用原料为一级行：

```text
脱脂乳粉　乳制品　3家供应商
  ├─ 供应商A　型号A1　¥31.50/kg　完整度92%　更新于 2026-07-16
  ├─ 供应商B　型号B2　¥29.80/kg　完整度85%　更新于 2026-06-28
  └─ 供应商C　型号C3　¥34.20/kg　完整度100%　更新于 2026-05-12
```

通用原料行显示名称、分类和供应商数量，不显示更新时间。展开后的供应商版本行显示供应商、型号/规格、价格、数据完整度、最新更新日期和操作。

搜索同时匹配通用原料名称、分类、供应商、型号/规格、内部编号和研发备注。内部编号不作为默认可见列。

### 4.2 创建与编辑

1. 新建通用原料，只填写名称和可选分类。
2. 立即为其添加第一个供应商版本，选择或新建供应商。
3. 供应商版本编辑器分为“基本信息”和“营养成分”两个页签。
4. 基本信息记录型号/规格、价格、单位、密度、来源、研发备注和可选内部编号。
5. 营养页签选择每 100g 或每 100mL 基准，录入内置项目并可添加自定义成分。
6. 可以复制一个供应商版本，再更换供应商并修改差异数据，减少重复录入。

草稿仍按供应商版本自动保存。检测到兼容草稿时只提示恢复，不静默覆盖当前表单。

### 4.3 营养录入和换算

营养输入框留空表示未知，输入 `0` 表示确认是零。界面必须明确提示这一区别。

每 100mL 数据参与质量基准配方计算时使用该供应商版本的密度换算。缺少密度时保留原始营养数据，但阻止需要质量换算的计算，并指出缺少密度的供应商版本。

完整度不仅显示百分比，还能展开查看具体缺失的内置营养项目、价格、密度或来源。未知值不计入已完成项目。

### 4.4 同类供应商比较

用户可在同一个通用原料下选择两个或更多供应商版本，比较：

- 价格和价格单位。
- 密度。
- 内置及自定义营养成分。
- 数据完整度和缺失项。
- 最新更新日期。
- 来源和研发备注。

比较中的未知值显示“未知”，不作为零参与差值、排序或高低判断。第一版不支持跨通用原料比较。

## 5. 保存、归档和引用安全

- 通用原料名称必填，分类可空。
- 供应商版本必须关联活动供应商；型号、内部编号、价格、密度和营养允许逐步补充。
- 所有正式写入使用事务。任一字段保存失败时整次写入回滚，草稿继续保留，编辑窗口不关闭。
- 正式保存成功后才更新供应商版本 `updatedAt`。
- 已被配方版本引用的供应商版本不能物理删除，只能归档；历史配方继续使用冻结快照。
- 通用原料下仍有活动或被引用供应商版本时不能物理删除。
- 分类或供应商被引用时不能物理删除，优先归档。
- 配方工作台只能选择活动供应商版本；历史版本仍可读取已归档版本。

## 6. 应用服务和持久化边界

React 继续只依赖类型化 `DesktopApi`。接口从当前扁平 `Ingredient` 调整为：

- 分类查询、创建、重命名、归档。
- 通用原料查询、创建、更新、归档。
- 供应商查询、即时创建、更新、归档。
- 供应商版本查询、创建、复制、更新、归档。
- 营养定义和值的读取与事务保存。
- 同一通用原料下的供应商比较数据读取。

浏览器演示适配器和 Tauri/SQLite 适配器实现同一契约。Rust 只负责持久化、事务、迁移、系统时间和错误映射，不重复 TypeScript 计算引擎中的营养换算规则。

SQLite 初始迁移需要建立分类、通用原料、供应商、供应商版本、营养定义和营养值表，并启用外键。当前浏览器演示 schema 从 v1 升级到 v2 时，演示记录转换成通用原料和对应的演示供应商版本；用户创建的浏览器演示记录不得静默丢失。

## 7. 错误处理

- 名称为空、引用已归档实体或十进制格式非法时返回字段级错误。
- 重复供应商版本先警告，只有用户确认后才允许提交。
- 每 100mL 营养缺少密度时允许保存原始数据，但返回换算能力警告。
- 供应商比较不因部分数据缺失失败，缺失单元格显示未知并列出原因。
- 更新时间由持久化层在事务提交时生成，前端不能传入或伪造。
- 数据库错误不得向界面泄露本地文件路径或 SQL 内容。

## 8. 测试与验收

### 数据与仓储

- 自定义分类创建、重命名、排序、归档和引用保护。
- 通用原料与多个供应商版本的创建、展开查询和归档。
- 供应商即时创建和同名防重复。
- 可选内部编号为空时正常保存。
- 供应商版本正式修改后更新时间改变；草稿和失败事务不改变更新时间。
- 营养空值保持未知，字符串 `"0"` 保持确认零。
- 每 100g 数据直接保存；每 100mL 数据仅在密度存在时可换算到质量基准。
- 被配方引用的供应商版本不能误删。

### 前端工作流

- 创建通用原料并添加第一家供应商。
- 在分类选择器中创建自定义分类。
- 复制供应商版本并修改供应商、价格和营养。
- 搜索供应商、型号和研发备注。
- 展开通用原料查看供应商版本。
- 比较至少三个供应商版本，未知值不参与数值判断。
- 营养缺失项和完整度详情一致。
- 刷新后恢复供应商版本草稿，正式保存后清除草稿。

## 9. 明确不在本次调整范围内

- 供应商联系人、合同、采购、阶梯价、库存和准入管理。
- 跨通用原料的供应商比较。
- 自动抓取或识别供应商营养标签。
- 自动判断食品添加剂法定限量。
- 将系统推算营养覆盖为供应商原始营养数据。
- 恢复第一版标签功能。

# 第三阶段 3B：食品研发 Agent 验收清单

本清单用于验证食品研发 Agent 的模型配置、聊天、多资料识别、供应商分组、人工复核和安全边界。浏览器演示版可以验证完整界面流程；真实 API、Ollama、Codex CLI 和 Claude Code CLI 需使用 Tauri 桌面开发版。

## 1. 测试前准备

- [ ] 原料库的手工新增、编辑和表格导入在未配置模型时仍能正常使用。
- [ ] “设置 → 通用”中的“启用食品研发 Agent”默认打开，也可以手动关闭。
- [ ] 准备 8 份不含敏感信息的测试资料：
  - 3 份供应商 A 的脱脂乳粉资料；
  - 3 份供应商 B 的脱脂乳粉资料；
  - 2 份供应商 C 的乳清蛋白资料。
- [ ] 至少让两份同组资料包含一个不同价格，用于验证来源冲突。
- [ ] 记录测试前原料库中这三种供应商版本的数量，避免把演示数据误认为新导入数据。

## 2. 设置与模型切换

- [ ] 设置页只显示一张“自定义模型服务”卡，其中可切换“OpenAI 兼容”和“Anthropic 兼容”。
- [ ] 分别修改两个兼容模式的地址与模型，来回切换后配置不会丢失。
- [ ] 启用一个模型后，其他模型自动停用；重新启用旧模型时，它原有的配置仍然保留。
- [ ] API 密钥输入框重新打开时保持为空，仅显示“已保存”，页面和日志中不出现密钥正文。
- [ ] “测试连接”能够区分网络、鉴权、限流和超时问题；“测试功能”能验证结构化任务能力。
- [ ] 选择不支持图片的模型时，上传图片前能看到能力提示，并可另选图片模型。
- [ ] DeepSeek、Kimi 中国、智谱 GLM、MiniMax 中国、阿里百炼和火山引擎均可独立配置和启用。
- [ ] 自定义 OpenAI/Anthropic 兼容接口和 Ollama 可以修改服务地址与模型名称。

## 3. 全局 Chat

- [ ] 在原料库、设置和后续功能占位页之间切换，Agent Chat 保持同一段对话。
- [ ] 关闭再打开 Chat 不会清空消息；重启应用后消息仍然存在。
- [ ] 一次可以选择多个 JPG、PNG、WebP、PDF、DOCX、XLSX、CSV 或 TXT 文件。
- [ ] 文件可在发送前单独移除；停止任务后可以用原资料安全重试，不会重复复制附件。
- [ ] 首次向远程 API 发送文件时，必须显示当前模型服务名称并要求确认。
- [ ] Ollama、Codex CLI 和 Claude Code CLI 显示“资料仅交给本机配置处理”。
- [ ] Chat 只显示任务状态和最终结果，不显示模型的思考过程。
- [ ] 清空对话需要确认，且不会删除已保存原料和正式来源附件。

## 4. 多资料识别和草稿分组

- [ ] 上传 8 份测试资料后得到 3 张独立草稿，而不是 8 张或 1 张。
- [ ] 供应商 A 与供应商 B 的脱脂乳粉分别成卡；供应商 C 的乳清蛋白单独成卡。
- [ ] 同一原料、供应商和型号/规格的多份资料合并到同一张卡，并列出全部来源文件。
- [ ] 供应商或型号/规格不同的资料不会自动合并。
- [ ] 一份文件中有多个原料或供应商时，可以拆分为多张草稿。
- [ ] 没有归入任何草稿的附件仍保留在任务中，并显示“未归入任何草稿”的提醒。
- [ ] 同一字段来源冲突时，该字段保持空白，显示来源不一致提醒，并保留所有来源附件。
- [ ] 一张草稿识别失败时，其他草稿仍能打开、复核和保存。
- [ ] “重新识别、合并、拆分、放弃”都只影响当前任务中的草稿。

## 5. 人工复核和正式保存

- [ ] 点击“打开并检查”后可修改通用原料名称、分类、供应商、型号/规格、价格、密度、营养、过敏原、来源和研发备注。
- [ ] 复核页不显示内部编号。
- [ ] 关闭或取消复核不会创建分类、供应商、营养成分定义或正式原料。
- [ ] Agent 完成识别后，原料库中仍没有新增正式版本。
- [ ] 只有点击“保存供应商版本”才写入原料库。
- [ ] 保存一张卡后，仅该卡变为“已保存到原料库”，其他未保存草稿仍然存在。
- [ ] 保存两个脱脂乳粉草稿后，同一通用原料下存在两个不同供应商 ID 的版本。
- [ ] 营养值 `0` 保存后仍为已确认的零；留空值重启后仍为未知，不会互相转换。
- [ ] 重启应用后，已保存的两个版本、未保存的第三张草稿和原对话都仍然存在。

## 6. API、Codex CLI 与 Claude Code CLI 一致性

对下面三类模型分别执行第 4、5 节的场景：

- [ ] 一个已配置的 API 模型（可优先使用国内服务）。
- [ ] Codex CLI：设置页检测到可执行文件、版本和登录状态，连接测试与功能测试通过。
- [ ] Claude Code CLI：设置页检测到可执行文件、版本和登录状态，连接测试与功能测试通过。
- [ ] 三类模型看到的食品研发工具名称与权限一致。
- [ ] 三类模型都不能调用正式保存原料的能力。
- [ ] CLI 只访问本次选择的附件，不能枚举其他导入任务或本机目录。
- [ ] CLI 任务结束、取消或超时后，临时任务目录被清理，原导入任务和草稿仍可恢复。

## 7. 异常与恢复

- [ ] API 密钥错误时显示鉴权提示，不显示密钥或请求正文。
- [ ] 限流、网络断开和超时分别显示可操作的中文提示。
- [ ] 模型第一次返回格式错误时自动重试一次；连续失败后保留任务和附件供人工重试。
- [ ] Codex CLI 或 Claude Code CLI 未安装时，设置页给出明确提示，不影响其他模型和手工功能。
- [ ] CLI 登录过期时，连接测试提示重新登录，不读取或复制 CLI 的凭据文件。
- [ ] 停止任务会终止正在运行的模型或 CLI 进程，但不删除已经完成的草稿。
- [ ] 浏览器演示版只运行离线模拟，不启动本机 CLI，不调用真实 API，也不产生模型费用。

## 8. 常见问题

| 现象 | 检查方法 |
| --- | --- |
| `pnpm: command not found` | 运行 `corepack enable`，再运行 `corepack prepare pnpm@11.7.0 --activate`。 |
| 没有可用模型 | 在“设置 → LLM 模型”启用并完成一个模型卡；手工原料功能不受影响。 |
| 图片无法发送 | 换用支持图片的模型，或在设置中单独选择图片模型。 |
| CLI 未检测到 | 先在终端确认 CLI 已安装并登录，或在模型卡中填写可执行文件路径。 |
| 资料没有生成草稿 | 查看 Chat 中的失败提示；可停止后重试，原附件不会重复导入。 |
| 草稿字段为空 | 查看“需复核问题”和来源附件；来源冲突时系统会有意留空。 |
| 保存时提示重复版本 | 确认供应商和型号/规格，必要时回到草稿修改后再保存。 |

## 9. 自动化回归

在仓库根目录执行：

```bash
pnpm test
pnpm typecheck
pnpm build
cargo fmt --manifest-path apps/desktop/src-tauri/Cargo.toml --check
cargo clippy --manifest-path apps/desktop/src-tauri/Cargo.toml --all-targets -- -A clippy::filter-map-bool-then -D warnings
cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml --all-targets
```

以上检查不需要真实 API 密钥。HTTP 和 CLI 合约测试使用本机离线模拟。

# Ninka FoodLab 原创 Launch Video Storyboard v0.2

## 本版结论

本版已根据当前确认意见重新整理整片顺序、时间和运镜，作为下一步制作 Animatic 与 Remotion 工程的当前工作稿。`v0.1` 继续保留，不覆盖。

- 当前只完成 Storyboard，不生成最终视频。
- 主画幅：16:9 原生横版，建议 2560×1440。
- 帧率：30 fps。
- 当前建议成片：约 40.4 秒，即 1212 帧。
- 可调范围：约 39–42 秒；后续应根据 Animatic、真实界面可读性和音乐节拍微调，不把每一段时长锁死。
- 当前叙事：问题 → 产品出现 → 原料库 → 配方复算 → Agent 能力 → Agent 生成配方提案 → 数据聚合成品牌 → 品牌动态展示 → 尾帧。
- 第七幕只承担第六幕到品牌段的转场，不补充新功能，也不表现提案已经被采纳、保存或写入。
- 第八幕删除价值汇总文案，只做动态品牌展示。

## 一句话镜头顺序

**表格单元格增殖 → 单元格聚合成 Ninka 符号 → Logo 缩入真实应用 → 原料库选中可可粉 → 同一原料行进入配方工作台 → 修改克重触发整份配方复算 → 打开 Ninka Agent → 询问 Agent 能做什么 → 顺着同一对话生成可可饮品配方提案 → 六项原料与三个处理节点聚成九模块品牌符号 → Ninka FoodLab 品牌动态展示 → 极简尾帧。**

## 逐幕详细拆解

### 第一幕：表格管理问题

**上屏文字**

> 还在用表格<br>
> 管理配方和原料吗？

**镜头节奏**

- 00:00.0–00:00.5：米白背景上先出现少量表格线与光标，画面尚未拥挤。
- 00:00.5–00:01.3：第一行文字由裁切遮罩中进入，“表格”使用森林绿强调。
- 00:01.3–00:02.3：第二行进入；背景浮现原料、供应商、版本、克重等通用字段。
- 00:02.3–00:03.0：表格版本沿景深增殖，九个单元格被 Grain/Tomato 色点亮并向中心靠近。

**运镜**

- 使用轻微俯视、近似正交的视角，镜头从 0.97 缓推到约 1.04。
- “混乱感”来自版本层叠和字段重复，不来自高速抖动、旋转或报错弹窗。
- 结尾的九个高亮单元格必须成为第二幕的连续视觉对象。

**边界**

- 不出现 Excel Logo、专属图标或直接复刻 Microsoft Excel 界面。
- 文案始终是第一视觉层级，表格只承担语境和转场锚点。

### 第二幕：产品揭示

**画面**

- 九个高亮单元格停止增殖，沿不同深度的短路径聚合。
- 单元格轮廓逐渐变为 Ninka 品牌九模块；最终用真实 `ninka-symbol-color-dark.svg` 接管，确保几何准确。
- 副标题出现：**“食品研发的本地工作台”**。

**运镜**

- 相机延续第一幕的推近，不重置方向。
- 符号锁定后，相机不硬切；Logo 缩小并移向真实应用左上角，第三幕界面从其周围展开。
- Logo 缩入左上角时使用缓入快出再缓停，避免像普通 PPT 缩放。

### 第三幕：原料库

**信息顺序**

1. 左侧原料列表：按通用名称归类，光标选中“可可粉”。
2. 右侧供应商版本：供应商、型号/规格、当前含税价、数据完整度和更新时间。
3. 营养侧栏：营养数据，并可看到基本信息中的密度和研发记录入口。

**辅助提示**

- **“按通用原料归类”**
- **“供应商、型号与价格”**
- **“营养数据与完整度”**

一次只出现一个提示，提示贴近对应区域，不用半屏大标题遮住真实产品。

**运镜**

- 界面保持近正面，避免为了“炫酷”而倾斜到难以阅读。
- 镜头只做缓慢推近；视觉焦点通过遮罩、局部亮度和提示线沿左到右移动。
- 结尾不把镜头拉回左侧。“可可粉”选中行直接脱离原位置进入画面中心，承接下一段 match move。

### 第三幕到第四幕：可可粉 Match Move

**动作逻辑**

1. 原料库其余区域降低亮度并后退约一个景深层级。
2. “可可粉 / 低脂可可粉 CP-10”所在行浮起，名称保持清晰。
3. 供应商、型号、价格等字段在运动中淡出。
4. 克重、单位、投料等配方字段在相近位置交叉出现。
5. 配方工作台从这行原料的周围展开。

**真实性边界**

- 这是电影化 match move，不模拟“点击原料库即可一键加入配方”的产品功能。
- 光标在转场开始前停住，不虚构按钮、不增加点击。

### 第四幕：配方实时复算

**画面**

- 先让观众辨认配方工作台和当前原料行。
- 修改一项原料克重后，投料、出成、得率、营养和成本按因果顺序更新。
- 短句出现：**“改一处，整份配方一起复算。”**

**运镜**

- 前 1 秒稳住原料行；编辑发生后，镜头沿同一轴线推向汇总区域。
- 数值变化用局部高亮和短暂数字滚动表达，不让整块界面跳动。
- 每组关键数据更新后至少保持 18–24 帧，避免观众只看到数字闪烁。

### 第四幕到第五幕：真实入口打开 Agent

1. 所有联动数据更新并稳定。
2. 相机从局部汇总区小幅拉回完整工作台。
3. 光标移到真实存在的 **“Ninka Agent”** 入口并点击。
4. Agent 面板从入口位置展开，原配方作为当前工作上下文退到背景。

这一段使用真实产品入口，可以表现一次真实点击；它与“可可粉行进入配方”的电影化 match move 明确区分。

### 第五幕：Agent 能力介绍

**用户输入**

**Agent 回答结构**

> 结合原料库生成配方提案<br>
> 根据配料表与营养标签进行逆向估算<br>
> 复盘当前配方，整理下一轮打样建议<br>
> 正式写入前，需要你确认

**画面节奏**

- 00:18.0–00:18.7：Agent 面板完整停留，先让观众辨认对话工作区。
- 00:18.7–00:20.1：输入并发送问题。
- 00:20.1–00:20.5：短暂思考状态。
- 00:20.5–00:24.2：回答流入，四项能力依次形成清晰卡片。
- 00:24.2–00:25.0：四项能力共同停留，“生成配方提案”轻微强调，输入框重新获得焦点。

**运镜**

- 以稳定和可读为主，只做约 1.00→1.04 的慢推。
- 卡片落位时可以有 8–12 px 的轻视差，但不让相机跟着每张卡反复跳动。

1. 正在读取原料库中的具体供应商版本
2. 正在试算投料、营养、成本与数据完整度
3. 正在生成配方提案

**画面节奏**

- 00:26.7–00:28.1：三个处理状态依次完成。

**真实性边界**

- 使用隔离的合成演示数据，保留 **“演示数据”** 与 **“待复核”**。
- “低糖方向”是研发方向，不在画面中宣称产品已经满足低糖营养声称。
- 不点击接受、写入、保存或创建正式配方版本。
- 视频渲染过程不临时调用外部模型，演示状态固定可复现。

### 第七幕：九个数据节点聚合成品牌符号

这是第六幕到第八幕的纯视觉桥梁，不承载新功能说明。

**为什么用这条转场**

- 第六幕天然具有六条配方原料和三个 Agent 处理节点，正好形成九个视觉对象。
- Ninka 品牌符号本身由九个模块构成，能够把“产品证明”自然变成“品牌记忆”。
- 全程不需要假装提案已经写入系统，也不需要临时添加一个不真实的按钮。

**1.6 秒动作设计**

- 00:32.2–00:32.55：提案卡轻微前倾，相机快速推近；其余聊天界面降低亮度并虚化。
- 00:32.55–00:33.05：六项原料的行标记和三个处理节点脱离 UI，文字淡出，只留下九个几何模块。
- 00:33.05–00:33.45：九模块沿不同但同向的弧线路径汇聚，颜色逐步映射到 Ninka 的 Forest、Grain、Tomato 与 Cream 体系。
- 00:33.45–00:33.8：模块排列成 3×3 聚合种子并整体旋转 45°；运动快速减速，最终用真实品牌符号 SVG 接管。

**运镜**

- 相机不是横向擦除，而是直接推穿提案卡，形成从二维 UI 到品牌空间的深度穿越。
- 九模块汇聚时相机跟随中心点，最多只加很轻的景深视差，不同时叠加强旋转。
- 最后 8–10 帧必须把运动完全收住，让第八幕从稳定品牌符号开始。

**声音**

- 六条原料行和三个处理节点各对应一个极轻 data tick。
- 九个 tick 不是平均机械排列，而是逐渐加密，形成向上的节拍。
- 聚合瞬间使用短促空气声与克制的品牌 hit，不用爆炸、重低音撞击或数码 glitch。

### 第八幕：动态品牌展示

第八幕不再出现“数据默认留在本地”“AI 只能提案”“正式数据由人确认”等价值汇总文字，也不再承担解释任务。

**画面**

- 深森林绿背景中，聚合完成的 Ninka 符号位于画面中心。
- Grain 与 Tomato 模块保留极轻的余势，随后回到准确的官方几何位置。
- 相机缓慢拉开，符号向左侧品牌位移动。
- 真实 `Ninka FoodLab` 横向品牌组合从符号后的遮罩中显现，并成为唯一主体。

**运镜**

- 使用约 3–5° 的小幅弧线移动和浅景深视差，制造品牌片的空间质感。
- 不做完整 3D 翻转，不让 Logo 发生无法对应真实资产的形变。
- 动画末尾以真实 `ninka-lockup-horizontal-dark.svg` 接管，确保名称、字形和比例准确。
- 品牌名称严格写作 **Ninka FoodLab**，不改成全大写 `NINKA`。

**文案**

- 本幕不放功能点、不放免责声明、不放营销句。
- 只允许品牌名称本身出现；定位语留给第九幕。

### 第九幕：极简尾帧

**画面**

- 定位语出现：**“食品研发的本地工作台”**。
- CTA 区域保留，但在文案确认前不写入正式成片。

**运镜与停顿**

- 00:37.7–00:38.5：定位语淡入，CTA 如已确认则随后出现。

## 整片运镜系统

### 一条连续的相机路径

1. **00:00.0–00:05.8：从表格进入产品。** 相机持续向前，表格单元格变成品牌九模块，Logo 再缩入真实应用。第一处产品出现不是硬切。
2. **00:05.8–00:17.2：横向读取产品，再深入配方。** 相机保持近正面和缓推，注意力沿原料库左侧到右侧单向移动；通过可可粉行 match move 进入配方工作台。
3. **00:17.2–00:32.2：进入 Agent 后稳定阅读。** 先小幅释放镜头，再推入 Agent；之后以稳定慢推和纵向跟随为主，让文字和配方真正可读。
4. **00:32.2–00:37.0：推穿 UI，进入品牌空间。** 第七幕负责全片最快的一次前向运动，随后第八幕以受控拉远把速度收住。
5. **00:37.0–00:40.4：归位并锁定。** 品牌组合进入尾帧后不再切镜，给观众留下清楚的品牌记忆。

### “丝滑、炫酷”的具体执行规则

- 炫酷感主要来自连续对象、景深、match move、遮罩、视差和节拍，不来自持续晃动或无意义的 3D 翻转。
- 一个节拍只保留一个主运动：推近、横移、拉远或旋转四者不要同时强烈发生。
- UI 证明段保持近正面，常规缩放控制在约 1.00–1.08；只有第七幕穿越瞬间可以短暂放大到约 1.25–1.35。
- 进入动作建议使用 `cubic-bezier(0.16, 1, 0.3, 1)` 或低回弹阻尼弹簧；品牌落位禁止明显弹跳。
- 关键文字、数字和完整配方卡在运动结束后至少保持 18–30 帧。
- 动态模糊只用于转场和快速位移，UI 停稳后必须恢复锐利。
- 相机总体方向是向前进入产品，再拉远进入品牌；避免每幕任意左右反转。

## 3. 可提取的镜头语言

### 叙事结构

这条片并不是连续录屏，而是反复交替两种段落：

1. **一句强结论或痛点**：白底/黑底大字，迅速清空认知负担。
2. **一个 UI 证明动作**：每次只证明一个流程结果，例如提交、评论、完成、排期。

这种“文案重置 → UI 证明 → 文案重置”的节奏比逐功能罗列更像 Launch Video，也是 Ninka 最值得借鉴的结构。

### 排版

- 使用现代无衬线字体；无法仅凭画面可靠确认具体字库。
- 标题常超过安全区或被画幅裁切，形成速度和尺度感。
- 一屏通常只突出一个句意；次要信息不与主标题争夺注意力。
- 关键词通过颜色、状态变化、品牌图形或行内替换获得强调。
- 白底与黑底反转承担章节标点，不依赖复杂转场插件。

### UI 呈现与相机

- UI 不是平铺截图，而是作为舞台道具：卡片浮起、缩放、前后分层。
- 主要仍是正视或轻透视，不靠夸张 3D 旋转掩盖界面内容。
- 光标既解释操作，也承担观众视线引导和转场锚点。
- 大界面在需要解释时展开，在只需证明一个动作时折叠为局部卡片。
- 常见相机动作包括缓慢 push-in、快速 snap zoom、圆形穿越、景深聚焦和卡片视差。

### 动画与转场

- 硬切用于白/黑背景重置，是全片最重要的节奏工具。
- 圆形遮罩、紫色 blur/whip、推镜和 UI 元素 match move 只在叙事阶段变化时使用。
- 字幕动画以单词或短词组为单位，不是整段同时淡入。
- UI 动画以“输入 → 状态变化 → 结果出现”为最小闭环。
- 动画速度快，但每个镜头只传递一个主要信息，因此仍然易读。

## 4. 声音设计（已验证与待听辨项分开）

### 已验证

- 整体响度约 **-16.99 LUFS**，True Peak 约 **-4.37 dBTP**，动态范围 LRA 约 **3.0 LU**。
- 音轨从约 00:00.216 持续到 00:55.180，只有开头和结尾存在明显静音。
- 波形在 15.808、22.581、40.629、42.304、48.992 秒附近出现较强瞬态；其中多处接近镜头或动画重音。

### 需要人工听辨后再定案

- 自动节拍分析给出 180、177.33、174.67、142.33、139.67 BPM 等多个候选，说明切分音或倍速关系较强，不能据此宣称准确 BPM。
- 仅凭波形不能可靠区分每个瞬态究竟是鼓点、点击、whoosh 还是其他音效。正式复刻节奏前需要逐段监听并建立 cue sheet。
- 原视频音乐和音效只能用于分析，不能直接用于 Ninka 成片。

## 5. 对 Ninka 的转译原则

应保留：

- “强文案 → UI 证据”的交替结构；
- 光标作为演员；
- 一镜头一主信息；
- 文案尺度变化、硬切重置和少量重点转场；
- 声音重音与状态变化精确对齐。

应改写：

- 使用 Ninka 的 Forest / Grain / Cream 品牌语汇，不复制天空、云层、Windows 山丘和紫色扫光。
- 用食品研发的真实闭环替代视频生产流程：供应商原料 → 配方复算 → Agent 提案 → 人工确认 → 标签/报告。
- 不照搬 56 秒长度。第一版建议控制在约 36 秒，让产品承诺保持单一清晰。
- 不宣称“合规完成”或“AI 自动改配方”；只展示研发估算、风险提示和受控人工确认。

# 第四阶段：配方工作台与配方库验收清单

本清单用于验证从供应商原料选择、实时计算、正式版本、半成品引用到版本比较的完整食品研发闭环。浏览器演示版和 Tauri 桌面版应遵守同一业务规则；正式研发数据建议使用 Tauri 桌面版的本地 SQLite。

## 1. 测试前准备

- [ ] 原料库至少有两种通用原料，其中一种原料有两个不同供应商版本。
- [ ] 两个供应商版本分别填写价格、型号/规格、营养和过敏原。
- [ ] 至少一个按体积计量的原料填写密度，另准备一个缺少密度的测试版本。
- [ ] 记录测试前配方数量，避免把浏览器演示数据误认为正式资料。
- [ ] 如果使用浏览器演示版，确认数据键为 `food-rd.browser-demo.v8`。

## 2. 配方建立与自动保存

- [ ] 新建成品配方后，名称、类型和计划投料总量可以编辑。
- [ ] 内部编号和标签保持可选；不填写也能继续研发。
- [ ] 选择原料时必须落到具体供应商和型号/规格，不能只选择通用原料组。
- [ ] 同一通用原料的不同供应商版本可以分别加入不同配方。
- [ ] 用量支持 `mg`、`g`、`kg`、`mL` 和 `L`，换算结果一致。
- [ ] 输入无效数字时保留原输入并指出所在行，不把无效文本静默改成 `0`。
- [ ] 草稿自动保存；关闭再打开后名称、用量、单位、顺序和备注仍在。

## 3. 锁定与补足

- [ ] 指定一种原料为“补足”后，其用量自动等于计划投料总量减去其他原料总量。
- [ ] 修改未补足原料时，补足项实时变化，当前投料合计保持计划投料总量。
- [ ] 当前投料合计以只读计算结果展示，且修改下方配方用量后立即更新。
- [ ] 只能有一个自动补足项；切换补足项后旧项取消。

## 4. 实时营养、成本与目标

- [ ] 同时显示整批和每 100 g 营养；填写出成重量后按出成重量计算。
- [ ] 留空营养显示为未知，已确认的 `0` 显示为零，两者不会混淆。
- [ ] 缺少任一原料营养时显示部分数据和具体缺失原料。
- [ ] 成本分别显示原料、包装、附加、整批、每 kg、每 100 g、每份和每包装的可用结果。
- [ ] 修改用量、计划投料总量、出成重量、包装或附加成本时结果实时更新。
- [ ] 体积原料缺少密度时指出对应原料，不能假装完成换算。
- [ ] 可以建立营养或成本上下限目标，并显示已达到、低于、高于或待计算。
- [ ] 过敏原汇总区分“含有”和“可能含有”，并可追溯到配方项目。

## 5. 正式版本与半成品

- [ ] 保存正式版本前出现人工确认窗口，列出用量、成本、完整度、目标、过敏原和警告。
- [ ] 至少一种有效原料、有效单位和正计划投料总量是保存正式版本的必要条件。
- [ ] 保存 V1 后自动生成“基于 V1”的工作草稿，V1 本身不可修改。
- [ ] 原料价格、营养或供应商资料后续变化时，V1 的冻结快照不变。
- [ ] 第二次保存得到 V2，不覆盖或复用 V1 的版本号。
- [ ] 半成品选择器只列出正式版本，不列出其他配方的工作草稿。
- [ ] 半成品出现新版本时，现有配方不会自动升级，必须由用户明确点击升级。
- [ ] 系统拒绝直接引用自己和通过其他半成品形成的间接循环。

## 6. 配方库与当前价格

- [ ] 可按名称、可选编号、标签、成品/半成品、正式/草稿/归档状态和更新时间筛选。
- [ ] 列表显示最新版本、计划投料总量、整批成本、更新时间和引用数量。
- [ ] 切换 V1/V2 时，原料、营养、成本、目标、过敏原和备注随冻结版本变化。
- [ ] “按当前价格重算”使用原料库最新供应商价格，并明确标注为临时结果。
- [ ] 临时重算前后的冻结版本成本保持不变；关闭或切换版本后不写入任何正式数据。
- [ ] “复制为草稿”进入所选配方，而不是列表中的其他配方。
- [ ] 归档需要二次确认；被其他正式版本引用的配方显示保护原因且不能归档。

## 7. 版本比较

- [ ] 默认以次新版本为基准、最新版本为对比，两个版本可以交换。
- [ ] 配方组成分别显示新增、移除、用量变化和供应商/型号或半成品版本变化。
- [ ] 供应商变化同时显示变更前与变更后的供应商和型号/规格。
- [ ] 营养、成本和目标每行同时显示 V1、V2 和差值或变化说明。
- [ ] 未知营养变为已确认 `0` 时显示“未知 → 0”，而不是“无变化”。
- [ ] 成本增加和减少使用不同但克制的颜色，不把营养升降擅自解释为好坏。
- [ ] 过敏原比较区分“含有”和“可能含有”。
- [ ] 研发备注变化同时显示两个冻结文本；没有变化的分区明确说明无变化。

## 8. 重启与双运行模式

- [ ] 浏览器刷新后，草稿、V1/V2、半成品引用和版本比较仍可读取。
- [ ] Tauri 应用完全退出并重新打开后，本地 SQLite 中的数据仍在。
- [ ] 浏览器演示 API 和 Tauri API 对同一两个版本返回相同字段和未知/零语义。
- [ ] 被引用保护、循环拒绝、版本不可变和复制草稿在两种模式下结果一致。
- [ ] 浏览器演示版不读取 SQLite；Tauri 桌面版不依赖浏览器 `localStorage`。

## 9. 响应式与可访问性

- [ ] 1568×1003 桌面尺寸下，配方表和详情/比较面板同时可见且无页面级横向滚动。
- [ ] 约 1042px 宽度下，主操作、筛选和冻结详情仍可读。
- [ ] 540px 手机宽度下，列表在上、详情或比较在下；宽表只在自身区域横向滚动。
- [ ] 搜索、筛选、版本选择、复制、比较、归档确认和关闭按钮可用键盘访问。
- [ ] 归档确认窗口具有明确标题，取消不会改变数据。

## 10. 自动化回归

在仓库根目录执行：

```bash
pnpm test
pnpm typecheck
pnpm build
cargo fmt --manifest-path apps/desktop/src-tauri/Cargo.toml --check
cargo clippy --manifest-path apps/desktop/src-tauri/Cargo.toml --all-targets -- -A clippy::filter-map-bool-then -D warnings
cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml --all-targets
```

上述测试不需要真实模型、API 密钥或联网。需要临时端口的 HTTP 合约测试只会在本机启动离线模拟服务。
